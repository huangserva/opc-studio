# 内容工作台 · 本机 X 发布扩展 0.1.33

在本机已登录的 Chrome 中上传 X Articles。工作台传入已保存的固定版本，扩展自动创建并绑定草稿，填写标题、富文本正文、封面，按文章包中的顺序和段落位置上传配图。执行不依赖 Codex 对话持续运行。

## 操作

1. 打开作品，保存修改，进入「平台准备 → X → 本机 X 发布」。
2. 填写目标账号，点击「上传到 X 草稿 / 继续任务」。扩展核对 X 页面实际登录账号；不匹配时停止。
3. 等待「等待预览确认」。点击「查看 X 完整预览」，核对正文、封面和全部配图。
4. 点击「核对预览并确认发布」，勾选核对项，再确认公开发布。上传草稿不会公开发布。

目标账号按作品记住。修改目标后，操作区只显示该账号的任务；其他账号的任务收在「其他账号历史任务」中，保留原账号和草稿绑定。新账号没有任务时，点击「上传到 @账号 的 X 草稿」创建独立任务。修改工作台目标不会替你切换 X 登录账号，扩展仍会核验二者一致；上传执行期间锁定目标，避免中途误改。

中断后回到同一作品、同一版本，点击「继续上传」。任务始终绑定原草稿。已经提交但结果不确定的图片，先重读草稿核验，不能直接再次上传。确认原草稿不可访问时，界面才提供保留旧记录、另建草稿的操作。

第一次安装：在 `chrome://extensions` 开启开发者模式，加载本目录，再刷新工作台和 X 页面。已有安装只需点击本扩展卡片上的刷新图标。工作台会核对扩展版本；页面刷新后必须确认新的页面执行器已就绪，不能向即将关闭的旧页面发送上传指令。

## 每篇文章共用的检查

- 固定作品版本、目标账号、文章包摘要和草稿链接；重试不重复新建。
- 保留标题、正文、标题层级、加粗和引用的原始 HTML。正文回读支持 X 把表情转换为图片的情况。
- 配图标记在提交前移除；通过原生 Insert / Add Media 文件控件上传。
- 记录每张图的源文件摘要、X 原生媒体块身份及正文前缀。对比源图像素；X 压缩较强时，还必须在源包中唯一匹配，不能只靠数量判断身份。
- 图片位于正文开头、末尾或连续排列时，也核对实际位置。发现插错或媒体块丢失时，仅在源文与其他配图均一致的条件下进行一次有记录的修复；重复失败停止并保留现场。
- 每次文件提交先落盘待核验记录。只有重载后确认文件确实未加入、其他正文及配图均正确，才允许一次有记录的重试。
- 保存后重新加载同一草稿，检查标题、全文、段落结构、图片身份、顺序、位置、封面和残留标记。正文出现多余断段时，仅修复可与源段落完整对应且不跨配图的范围。
- 后端必须收到正文、段落、顺序、位置、封面的检查证据，才允许进入发布确认。仍需用户查看原生完整预览。
- 发布尝试先记录状态；没有真实发布链接的未知结果不会自动再次点击发布。

## X 实际媒体限制

扩展捕获 X 页面真实拒绝提示，并记录当时账号和正文已接受的图片数量。工作台据此为该账号的后续文章做上传前检查；没有实际证据时，不猜测上限。

进入上传区时即检查正文图片数量，明确显示「原稿多少张、该账号已实测单篇上限多少张、超出多少张」。确认超限后禁用上传、继续上传、另建草稿和发布；后端也会在创建任务、下发上传内容和确认发布前再次检查，避免旧页面绕过提示。

尚未验证上限的账号会明确标注。若原稿超过本机其他账号已实测的上限，会先显示带账号来源的参考提示，不把其他账号的观察值当作当前账号的确定上限。首次遇到 X 原生媒体超限提示，插件立即记录并停止，后续图片不再提交，也不等待上传超时。

分批上传不能增加单篇文章容量。上传页不再提供分篇适配入口，不自动拆篇或省略图片；历史分篇作品和记录保留，但两份草稿是两篇独立文章，不能当作原长文完整上传成功。

一次本机草稿测试观察到：已加入 25 张正文配图后，第 26 张被 X 提示 `exceeds the media limit per Article` 拒绝。这是该账号本次运行的观察值，不是所有账号永久固定的规则。X 后续修改限制时，应重新核验。
