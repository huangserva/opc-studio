# 工作台端到端回归

项目根目录执行：

```sh
node tests/e2e/run.cjs
```

前提：合同指定的 `../article-importer/.venv/bin/python` 可导入工作台依赖、Node 可运行项目 `pi-runtime/`、本机已有 Chrome。Playwright 优先读取本目录安装包，也支持 `E2E_PLAYWRIGHT_PATH`；当前宿主已有 Codex runtime 的 Playwright 时可直接复用。缺依赖会明确失败，不会在运行时联网安装。

在其他宿主准备依赖（单独执行，不属于离线测试运行）：

```sh
npm install --prefix tests/e2e
```

默认真实 Chrome 无头运行。可设置 `E2E_BROWSER=chromium` 使用已安装的 Playwright Chromium，或 `E2E_HEADED=1` 显示窗口。套件不自动下载浏览器。

运行结果保存在 `coordination/evidence/e2e/<UTC时间>-<pid>-<随机>/`：每例截图、额外的删除后检索/来源已删除/刷新进行中截图、`results.json`、`result.txt`、`server.log` 与 `blocked-network.jsonl`。任一用例或启动器失败返回退出码 1；通过与明确跳过返回 0。跳过原因写进 JSON，不计为通过。运行出错也会保存截图并继续后面的独立用例，启动/公共准备失败则记为启动器失败。

## 隔离范围

- 每次创建全新临时 workspace，证据目录带本进程 pid，独立应用与模型端口，禁止选择生产 8766/3000。端口若被占用会换一个再试。
- 结束时先对子进程组发 SIGTERM。macOS 上组里只要有一个进程发不了信号，`kill(-pid)` 会返回 EPERM 且整组都收不到信号；这时改 `child.kill()`，并只向这棵进程树的正 pid 补发信号，然后确认进程已经退出。确认不了就记清理失败，不把套件算作通过。不会对父进程所在的进程组发信号，因此并行的另一个套件不会被误杀。
- `server_fixture.py` 调用产品 `server.main()`，真实运行 Handler、SQLite 入库/删除/检索、即时分析、PiRuntime 与调度器。
- `ARTICLE_STUDIO_MODEL_CONFIG` 只指向本轮本地固定响应服务；支持 JSON 和 SSE、真实 `image_url` 分支，无 API Key。模型请求证据只记录类型，不记录内容或密钥。
- 知识库来源设为空，不扫描个人资料；网页、公众号文章、合集、搜狗和微信来源状态边界替换为脱敏夹具。未登记网页直接失败；产品流程与业务方法保持原样。测试里不给后台凭证，并拦截钥匙串读取。
- Python socket 与 DNS 只允许本轮两个本机夹具地址；Pi 的 Node 子进程加载 `network_guard.cjs`，只允许同样两端口。浏览器拦截非本轮应用 origin，禁用 service worker 和后台网络功能。所有页面按钮仍请求真实独立工作台 API，仅“前后端版本不一致”用例故意拦截 analysis-status 为 404。
- 正常结束或测试失败，先关浏览器；`browser.close()` 超过 10 秒就改对浏览器进程发 SIGKILL，再停独立应用进程组与模型服务，删除临时 workspace。JSON 记录清理状态。证据写完后退出，避免关浏览器卡住时清掉总超时。证据保留。

2. 删除确认、列表消失、删除前检索命中/删除后 API 与知识库页面检索不命中；卡库标来源已删除；同链接重新收下有新回收项。
3. 链接+图片一次提交一条回收项，识别与分析完成。检测到 `coordination/intake-combo-vision-report.md` 才启用，Pi 未交付则按合同跳过。已经写好完整断言，后续交付后同一命令自动覆盖。
4. 真实手动补合集与抓历史；等 POST 202 后检查两个按钮禁用；刷新检查仍禁用；结束解锁；真实列表显示合集来源，搜狗仅标题无伪链接。夹具合集等待四秒保证观察窗口；搜狗解析夹具返回空链接，不模拟验证码中断。
5. 平台分栏：已接通四平台、规划中五平台且没有抓取按钮；不冒充这些来源已配置真实账号。
6. 真实界面创建、显示和手动运行创意提炼任务。新资料第一次卡片调用故意返回 503，使其留下可兜底条目；定时运行真实调用本地模型成功，校验 checked≥1 与运行记录 succeeded。
7. 模拟 analysis-status 404，页面显示需要重启。
8. 额外：仅图片→真实 ProfileVision/PiRuntime→本地模型 image_url→识别与分析完成。第3项未交付时仍能验证模型服务的视觉分支。

此套件证明当前产品代码在本地夹具下的用户路径；真实外部服务可用性、生产部署是否加载新代码仍需独立验收。发现产品缺陷时记录失败，不在此目录改产品代码。

9. 回收项删除：确认框解释共用正文、即时分析、卡片保留与不可撤销；取消时零删除请求、数据快照不变；确认后列表移除且刷新仍消失。同链接两个回收项必须真实共用 document_id，删一个后正文检索结果和另一条保持不变。
10. 卡片页：用临时 SQLite 夹具构造五类来源，每类候选 / 已确认 / 已驳回各一张；真实浏览器切换按来源 / 时间，逐个状态与来源筛选。单张删除和来源已删除组清理均验证取消零请求、确认删除、刷新持久化，保留其他卡片与来源；图片 / 视频仅是类型夹具，不触发真实媒体识别。

`cards_fixture.py` 仅在新建临时 workspace 初始化数据，不新增测试 API，不替换产品卡片列表 / 删除逻辑。浏览器禁止请求与后端禁止连接统一记录；任何禁止地址尝试或 pageerror、清理未完成都会使套件失败。

11. 知识库先收藏的链接：调用产品 `/api/knowledge/reference` 保存独立标题和 reader_note；回收站再收下同链接，验证复用 document_id；通过真实确认框删除回收项，核对收藏、标题、评论和检索结果。`review6-fixes-a-report.md` 未交付时仍真实执行并记录 `known_defect_reproduction`（不计通过/失败），证据明确实际是否复现；报告出现后自动改为严格回归断言，删掉收藏或确认框错误宣称删正文均失败。初始化或执行错误始终失败，不伪装为已知缺陷。

12. 同一 drop id 再交一张同格式图片：隔离实例先经真实 `/api/intake/stage` 与 `/api/intake/drop` 收下图片并回读 `/file` 的 sha256，再用新 stage token、同一 id、另一张 PNG 提交一次。原附件字节必须不变，且仍能回读原图。`combo-fixes-stage-report.md` 未交付时记 `known_defect_reproduction`；交付后按该期望断言。第一次收下或回读失败仍算用例失败。

13. 上传中改选：真实 Chrome 用路由拦住 `/api/intake/stage` 的回执（不改产品）。先选 A 并点收下，请求还在飞时改选 B。A 必须提交成功。之后 B 仍显示在「已选」里，或上传期间文件框被禁用且页面明确说不能改选，都算通过；B 一度出现随后被静默清掉算缺陷。启用条件与 12 相同。

14. 组合图片实际格式：真实 Chrome 表单分别收下“链接 + 无后缀 PNG（noext）”和“文字 + 名为 fake.jpg 的 PNG”。回读真实 `/api/intake/{id}/file`，核对 `Content-Type=image/png`、原图 SHA256 和页面内解码 `naturalWidth>0`。列表没有内建图片预览，测试在本条 DOM 内插入明确标识的 `<img>` 探针，直接读取产品文件接口，不拦截或伪造图片响应。保存两条的响应类型、哈希、解码事件、截图。`fixes-a2-report.md` 不存在时仅记 `known_defect_reproduction`；报告存在时自动开启严格断言，任一类型、字节或解码不符都失败。收下、解析、分析或文件回读初始化失败始终失败。
