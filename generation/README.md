## illustration-generator（2026-10-02）

通过 `ARTICLE_STUDIO_IMAGE_SKILL` 指定已安装的 `illustration-generator` 目录；默认使用 `~/.codex/skills/illustration-generator`。风格资料由本机技能提供，不随仓库分发。

工作台使用原始 63 种通用风格、17 个分类、15 个模板，以及随技能附带的 20 种文章风格。两个生图入口均有「风格」选择；「按描述生成」保留原提示词。所选风格只影响提示词，生成执行仍是已有 Qwen/Krea 工作流。任务保存完整提示词、原用户描述和技能版本、风格、分类，重试不会重复拼接风格。

Pi 使用显式 skill 路径发现统一入口，按需以受限 `read` 工具读取技能资料，用 `get_image_styles` 查询风格。不启用任意文件读写、shell 或其他技能自动发现。参考图编辑、自动批量和工作台内的提示词收藏写入尚未接入，不能仅凭技能里的指南宣称可用。

本机技能的 Qwen CLI 改为提交工作台服务；七种 2K 预设显式传递宽高，使用已有队列检查和持久化状态。文章单图脚本使用随技能附带的风格资料，解除原机器的 Claude 共享库依赖。原仓库未修改或推送。

## 工作台使用

打开「AI 助手」，在聊天框输入 `@` 选择「生图」或「视频」，也可直接点「AI 生图 / AI 视频」。模型、尺寸和时长在输入框内切换并记住；填写描述后直接发送，结果出现在聊天卡片。明确选择工具无需等待聊天模型，聊天模型未配置时也可生图。发送后清除工具标签，下一句恢复聊天。种子与历史入口在「更多设置」。

`@生图 一只猫`、`@视频 海边日落` 可直接输入或粘贴。紧接生成任务说「再生成一次」会沿用原描述和模型、新建任务；「换成 Krea2」沿用原描述换模型。换话题或开始新对话后，不自动引用旧任务；可点击具体卡片的「再生成一张 / 换模型」把描述带回输入框，确认或修改后发送。单独说「对的」不会授权重跑历史任务。

普通明确自然语言请求仍通过聊天助手调用工具；未指定模型时使用已保存的默认生图模型。

- 图片：Qwen Image 2.1 BF16，20 步；Krea2 Turbo FP8，8 步，可在生图下拉框切换。聊天可明确说「用 Krea2 生成一张图片」，不会替换成其他模型。
- 视频：默认 MiniMax H3 Singularity ref2va INT8 + ref2v Turbo 8 步，文生视频，带 H3 原生音轨。当前提供约 2.3 秒试片 / 5.2 秒横竖视频；独立视频页另有首帧、首尾帧及多参考素材输入模式，实测状态见下文。
- 状态：连接、排队、生成、保存、完成、失败。进度、完成后的图片或视频、失败原因直接显示在聊天卡片中；刷新或收起助手后仍可找回，也可从「最近生成」查看。已提交任务不会因刷新重复生成。
- 成果：先预览，可下载、另存为独立图集/视频；图片可插入生成时选定的作品，保存新版本。原作品发生版本变化时拒绝自动覆盖。
- 聊天默认每轮最多提交一个媒体任务。提交成功不代表生成完成，卡片持续更新实际状态；失败后可点「查看任务详情」保留原描述并手动重新提交。
- 「文字封面／信息卡」仍是单独的本地排版能力，普通图片请求走真实图片模型。

## 助手部署查询

助手查询“4090 上有哪些模型、LoRA、节点”时使用 `get_backend_inventory`；查询显存、排队、连通性时使用 `get_backend_health`。可指定 `qi21`、`krea2` 或 `h3`，省略模型查询全部固定服务，并尝试读取 Strata 的固定 `/status`。本机调试入口为 `GET /api/generation/backend-inventory` 和 `GET /api/generation/backend-health`，可带 `?model=h3`。

查询复用现有 SSH，仅访问固定回环端口及只读接口，不加载、卸载、提交或重试模型任务。队列只返回数量，状态不返回命令参数、私有配置、提示词或凭据。某个接口失败会单独标记未知，保留其他服务的有效结果；SSH 失败时明确返回连接失败，静态接入配置不会冒充实际库存。

库存来自 ComfyUI 加载器当前公布的文件枚举，覆盖已接入服务，不扫描整台服务器磁盘。文件可选和节点已注册不表示模型已加载或已通过生成验证。ComfyUI 空队列不能说明整张 GPU 空闲，Strata 未返回的加载状态保持未知。

`get_capabilities` 返回配置、输入限制和限定配置的实测记录：独立生成页可创建六种 H3 模式并上传参考素材；聊天手动入口新任务仍为文生，可复用已有任务的完整配方；LLM 的 `generate_media` 工具保持当前文生参数范围。三种入口分别说明，聊天附件不自动作为参考素材。

### 本机记忆工具

Pi 注册 `remio_status`、`remio_search`、`remio_read`、`remio_create_note`、`remio_update_note` 及 `memos_status`、`memos_search`、`memos_write`。专用调用由这台 Mac 后端执行，通过 Pi 私有工具桥返回真实结果，不经过 GPU SSH 或通用 web_fetch。Pi 启动时校验实际注册工具集合；每次调用还会核对当前用户消息授予的权限。

remio 使用本机 CLI 连接桌面应用，搜索摘要和按 note_id 分页读取；返回真实笔记链接。MemOS 使用现有 MemOS Local 插件和 SQLite 库，读取主 Agent、公共与工作台记忆范围，关键词/FTS 检索明确标记 `semantic=false`。旧 8899 HTTP 服务不是此接入入口。读取以只读连接打开现有库，不启动插件运行时或执行迁移，也不依赖外部嵌入服务。

静态接入信息见 `/api/assistant/capabilities` 的 memory；固定只读连通探测见 `/api/assistant/memory`。健康探测不检索正文、不修改资料；安装声明和进程写权限不能代替一次真实保存成功的回执。服务错误与空检索结果分别返回。工具片段与知识工具共享每条消息 16000 字符预算；已知模型密钥在裁切前隐藏。

查询无需写授权；当前用户明确说“记住”“保存到 remio”才默认创建 remio 笔记，明确指定 MemOS 则写 MemOS。更新 remio 仅向本轮已读取并成功回传的笔记追加，保留原文。请求去重编号由后端产生，不能由模型覆盖；每条消息每个保存工具只提交一份不同内容，多项事实先合并，后续增补用下一条消息。未知保存结果不能反复新建请求重试。测试使用模拟 remio 保存及临时 MemOS 库，不在真实用户库创建测试笔记。

### SSH 远程查询

工作台助手另有真实 SSH 命令工具：`ssh_connection_status` 使用已配置主机执行 `true` 检查连接；`ssh_run_readonly` 直接在该主机执行经过验证的查询命令，返回实际命令、退出码、标准输出、错误输出、检查时间及超时/截断状态。它不依赖 ComfyUI API，可使用 `nvidia-smi`、`ps`、`ls`、`find`、`df`、`free`、日志读取及 `systemctl status` 等命令查询远端系统。

SSH 检测失败时，连接工具从本机可信 SSH 配置解析单个 ProxyJump 别名及回环转发目标，自动测试跳板连接并查询转发端口的 TCP 监听记录。附加诊断不会改变 GPU 的失败状态：跳板连接成功不能写成 GPU 已连接，端口监听也不能写成隧道健康。查询失败、超时、配置或输出不完整均报告未知；不支持的路由会跳过附加诊断。每一步分别限制时间和输出，探测时间预算合计 29 秒（GPU 10 秒、配置 3 秒、跳板及监听各 8 秒），另有本机进程清理开销。不会把完整 SSH 配置、身份文件路径或凭据交给模型，所有连接关闭配置中的附带端口转发。

此入口当前开放查询排查；不执行服务启停、文件修改、安装或部署。主机与身份沿用本机 SSH 配置，模型不能传入其他主机、端口或凭据。命令不允许管道、重定向、命令替换、脚本和 `sudo`，选项由后端验证。输出在读取时限制长度，超时或 SSH 退出码 255 不会写成查询成功。凭据路径检查属于参数检查，不是独立文件系统隔离。

本机可用 `GET /api/assistant/ssh` 检查真实连接，用 `GET /api/assistant/capabilities` 查看助手已接入的工具范围。能力声明与连接状态分别返回，固定服务库存查询与远程命令查询分别命名。

## GPU 调度边界

本工作台一次运行一个媒体任务；提交前检查 8188、8191、8192 的队列及 H3Storyboard 的现有 GPU 租约。有任务时拒绝新提交。切换媒体模型时仅释放另一个空闲 ComfyUI 实例的模型缓存，不终止进程、不取消其他任务。

与其他独立程序尚未共用一套原子租约协议，队列检查不能防止其他程序恰在检查后提交。不要同时从其他 UI 发起同一块 GPU 的任务。后续需要统一调度时，应在服务器侧建立共同遵守的调度接口；不要伪造 H3Storyboard 的任务记录。

生成节点报错、没有真实文件、文件校验失败都不会显示成功。长时间连接中断或等待超时不等于服务器任务已取消；应先检查原任务，不自动重复提交。

## 可见进度

任务卡片与详情面板显示当前执行阶段、每秒更新的已用时间、最近一次服务器确认及排队位置。通过现有 SSH 连接观察 ComfyUI `/ws`，使用任务原有 client_id 接收模型加载、提示词编码、采样、解码、导出事件；HTTP 队列和历史轮询负责确认完成、恢复和读取结果。重启后用已保存 prompt_id 恢复观察，不重复提交。

仅 KSampler 实际返回的 value/max 显示采样百分比；它不代表整项任务的完成比例。其他阶段和视频显示活动条及真实阶段，不估算百分比或剩余时间。服务器确认超过 20 秒未更新、请求失败或进度连接中断时明确提示正在核实/重连；计时不会冒充后端心跳。长提示词默认折叠，进度刷新沿用聊天滚动锚点，不拉走正在阅读历史的用户。

## 聊天图片附件

聊天框支持粘贴、拖入、点击「＋ 图片」上传 PNG / JPEG / WebP，每条最多 4 张，每张最多 10 MB。发送前可预览、移除；仅图片也可发送。服务端检查真实图像格式及像素上限、去除元数据、最长边缩至 2048；附件以本地文件保存，聊天中可点击查看。

图片通过 Chat Completions 的 `image_url` 多模态内容发送；当前 V100 千问接口已用实际图片验证识图。已分析的历史图片保留原图编号和文字结论，需要重新核对时由 read_chat_image 按需读取。展示历史保存本机文件引用；Pi 原始会话保留完整图片消息，模型上下文通过原生编辑替换为引用。

聊天框「＋ 图片」附件用于聊天模型看图，不自动作为生图或 H3 参考素材；带附件使用生成工具时会明确拒绝。H3 参考图、视频和音频从独立视频页上传；从已有 H3 任务选择再生成或修改描述时保留该任务的输入模式与素材编号。

## V100 聊天稳定性修复（2026-10-03）

文字上下文由 Pi 按所配置模型的 token 预算管理，接近上限时执行原生摘要压缩。已撤销额外的固定 24 轮和 96KB 供应商请求裁剪，旧版导入也不再截断为 80 轮。模型看到的内容来自 Pi 原生会话投影，统计与实际请求一致。

已经成功分析的图片通过 Pi 的 appendContextEdit 替换为原图编号；原始图片消息和后续分析结论保留。未完成、失败或找不到本机原图的图片不自动移除。read_chat_image 不传编号时可分页列出当前聊天图片，传编号时可按需重新查看原图，返回原生图片工具结果；下一次消息发送前，成功分析后的工具图片也会归档为引用。编号只能读取当前聊天已有附件，不访问任意文件或其他聊天。

旧版请求裁剪产生的使用量会通过一次原生上下文编辑作废，由 Pi 重新估算完整投影；后续使用真实服务返回的 token 用量。没有在 onPayload 中另行删改历史。

V100 的无响应超时为 600 秒，设置页面允许 10–1800 秒。流式请求收到事件会重新计时，持续输出的长回答不会因超过单个超时值而被强制取消。Qwen 的关闭思考设置通过 chat_template_kwargs.enable_thinking=false 传给服务。请求消息/图片数、停止原因和脱敏诊断保存在本机。

“本地回复”仅表示问候等由工作台直接返回固定文字，正常对话使用配置的模型接口。


## 视频调试页

`/lab.html?kind=video` 提供六种 H3 输入模式：

| 模式 | 必需输入 |
|---|---|
| t2v · 文生视频 | 描述 |
| i2v · 首帧生视频 | 描述、首帧图片 |
| fl2v · 首尾帧生视频 | 描述、首帧及尾帧图片 |
| r2v · 多参考素材 | 描述、至少一个参考图片、视频或音频 |
| ir2v · 首帧 + 多参考素材 | 描述、首帧图片、至少一个其他参考素材 |
| flr2v · 首尾帧 + 多参考素材 | 描述、首帧及尾帧图片、至少一个其他参考素材 |

t2v、i2v、fl2v 使用 Director；r2v、ir2v、flr2v 使用 H3 原生多参考节点。2026-10-05 已在自有 4090 完成这三条原生通路的真实生成：r2v 使用两张图片、带音轨视频和独立音频；ir2v 使用首帧和两张参考图；flr2v 使用首尾帧、参考图、带音轨视频和独立音频。测试配置为 Singularity / ref8 / 768×448，r2v 56 帧、其余 124 帧。已核验真实 H.264 / AAC 输出及工作台预览；其他权重、加速方案和尺寸未逐项 GPU 验证。实测状态表示该配置生成通路可用，不保证每种素材的参考效果；记录在 `work/h3-input-upgrade/live-validation.json`。

参考图片总计最多 9 张，包含首帧和尾帧，因此 ir2v 最多另加 8 张图片、flr2v 最多另加 7 张图片。参考视频最多 3 段，独立参考音频最多 3 段；所有素材合计最多 12 个，同样包含首尾帧。视频自带音轨会参与编号，但不额外占用文件数量。

每段源视频、源音频均须为 2–15 秒。所选源视频累计最多 15 秒，所选独立源音频累计最多 15 秒，两个总量分别核对，不能先裁短再绕过上传源时长限制。参考视频只使用开头，截取长度以本次输出时长为上限，并自动调整为模型支持的帧数；实际参考片段可能略短。56 帧约 2.3 秒用于短试片，124 帧约 5.2 秒用于较长生成。

权重、加速 LoRA 和附加 LoRA 分开选择。Singularity / ref2va 权重与 ref8 / ref4 加速方案适用于 t2v、i2v 和三种多参考模式；fl2va 权重与 fl8 / fl4 加速方案适用于 t2v、i2v、fl2v。Hybrid 权重与「不使用加速 LoRA」方案支持全部六种模式。页面按所选模式筛选可用选项，服务端再次检查兼容性。附加 LoRA 最多 3 项，强度 0–2；采样步数由加速方案决定，不接受独立 H3 步数或 CFG。全部选择写入 job.json 与实际 workflow.json。

图片通过 `/api/generation/references` 上传，支持 PNG / JPEG / WebP，每张最大 10 MB；服务端解码、转 RGB、缩至最长边 1280。视频和音频通过 `/api/generation/reference-upload` 发送原始文件，每个最大 100 MB，服务端核对实际类型和时长、转换为本地参考格式。素材保存于 generation/references，参数保存有序编号及展示信息。旧版单张 `reference` 参数兼容为一张参考图片；历史沿用会完整恢复素材，普通生成不带入上一条任务的素材。

除 t2v 外，输出宽高须为 32 的倍数，当前可选 768×448 或 448×768；图片和视频参考素材也会补齐到适用尺寸。上传和生成沿用本机访问及 Origin 校验，大工作流经 SSH stdin 传输。

页面只能选择已接入的真实服务，目前视频生成服务为自有 4090 H3。H3 权重选项不代表 LTX、Kling 等其他视频服务。
